HOUSEHOLD OBJECT RECOGNITION — CONTINUAL RECOGNITION PROJECT
==============================================================

PROJECT GOAL
------------

Build a continual household-object recognition system using the
CORe50 dataset.

The system must:

1. Learn household objects incrementally across sessions/batches.
2. Learn new object instances and/or new classes over time.
3. Minimize forgetting of previously learned objects.
4. Measure accuracy and forgetting after incremental learning.
5. Compare a naive continual-learning approach with an
   anti-forgetting approach.
6. Provide a simple web application.
7. Allow the user to open a public link on a phone.
8. Use the phone camera for live object recognition.
9. Show object name, confidence, and bounding box where supported.


==============================================================
DATASET
==============================================================

PRIMARY DATASET:

CORe50

Use the official CORe50 session structure.

Important dataset characteristics:

- 50 domestic object identities
- 10 object categories
- 11 sessions
- changing viewpoints
- changing backgrounds
- lighting variation
- occlusions
- sequential/session-based data

Do NOT flatten the dataset into an ordinary random train/test
dataset because the continual-learning structure is required.

==============================================================

The data must be presented sequentially.

Support:

1. NI — New Instances
2. NC — New Classes
3. NIC — New Instances + Classes

Use official CORe50 filelists/scenario definitions where practical.

The model must receive experiences sequentially.

Example:

Experience 1
    ↓
Train
    ↓
Evaluate
    ↓
Experience 2
    ↓
Train from previous model
    ↓
Evaluate
    ↓
Experience 3
    ↓
Continue

Rules:

- do not reset the model between experiences
- do not train on future experiences early
- do not leak test data
- preserve experience ordering
- make experiments reproducible

STATUS:
✅ COMPLETE


==============================================================
PHASE 4 — NAIVE CONTINUAL-LEARNING BASELINE
==============================================================

Implement the simplest continual-learning baseline.

Method:

Sequential training without replay.

Example:

Experience 1
    ↓
Train model
    ↓
Evaluate

Experience 2
    ↓
Continue training same model
    ↓
Evaluate old + new knowledge

Experience 3
    ↓
Continue training
    ↓
Evaluate again

Measure after each experience:

- overall accuracy
- old-class accuracy
- new-class accuracy
- per-class accuracy
- forgetting

This establishes the naive continual-learning baseline.

Do NOT train each experience from scratch.

STATUS:
✅ COMPLETE


==============================================================
PHASE 5 — ANTI-FORGETTING METHOD
==============================================================

Implement ONE practical anti-forgetting strategy.

PRIMARY METHOD:

Experience Replay

Concept:

New experience
      +
memory of previous examples
      ↓
training
      ↓
updated model

Maintain a bounded replay memory.

At every experience:

1. load current experience
2. sample replay examples
3. combine current + replay data
4. train
5. update replay memory
6. evaluate old + new knowledge
7. continue to next experience

Do not implement many continual-learning algorithms.

One strong method is enough.

STATUS:
✅ COMPLETE


==============================================================
PHASE 6 — CONTINUAL EXPERIMENT
==============================================================

Run the actual continual-learning experiment.

PRIMARY SCENARIO:

NIC

New classes + new instances.

For every experience:

- train
- evaluate
- record metrics
- update replay memory
- continue

Important:

- model state must persist between experiences
- future data must not leak backward
- test data must remain isolated
- training order must be documented
- seed/configuration must be recorded

Also run NI/NC when practical without causing unnecessary
computational cost.

PHASE 8 — FOCUSED ERROR + FORGETTING ANALYSIS
==============================================================

Keep this phase practical.

Analyze:

- forgotten classes
- difficult object identities
- class confusion
- viewpoint changes
- lighting changes
- background changes
- occlusion
- low-confidence predictions

Answer:

1. Which objects are forgotten?
2. After which experience does forgetting increase?
3. Which classes are hardest?
4. Does replay reduce forgetting?
5. What environmental changes cause failures?

Generate representative failure examples.

Do not turn this into a huge research thesis.


==============================================================
PHASE 9 — FINAL MODEL SELECTION
==============================================================

Do NOT automatically retrain.

Use the models already produced in Phases 4–6.

Compare:

- naive continual model
- replay continual model

Select the final model using actual measured:

- accuracy
- forgetting
- old-class retention
- new-class performance
- model size
- inference speed

Freeze the selected checkpoint.

Additional training is OPTIONAL only when Phase 8 identifies a
specific problem worth the computational cost.
